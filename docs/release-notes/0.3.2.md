TimeBox is a macOS menu bar utility for task rotation timeboxing:

> The timer controls **how long you work on a task**, not whether the task is completed.

0.3.2 is a fix release. Two things were reporting or granting the wrong number: a day's worked time when a block crossed midnight, and the `+5 min` button during a break.

## A day's work is now measured by the day, not by the block

Work that ran past midnight was credited entirely to the day the block *started*. Start something at 23:32, park it, pick it up the next afternoon and finish at 15:00, and the whole hour and forty minutes landed on the first day — the second day, the one you actually spent on it, read `Worked 0m`.

The cause was an assumption that a block is an interval. It is not: a block can be paused, parked overnight, extended and resumed for days, so the moment it started says very little about when its time was spent.

Every start, resume, pause and stop is now recorded as a span of its own, and a day's worked time is the part of those spans that falls inside that day. A block worked 23:40–00:10 gives the first day 20 minutes and the second 10 — neither losing the time nor counting it twice — and the second day's top-tasks list credits those 10 minutes to the task they belong to. An interval you were paused for counts on neither day, which is what it always meant.

**Days recorded before this release are not recomputed.** There is no per-interval record for them to be recomputed from, so a block written by an earlier version keeps its old whole-block attribution. A past day reads exactly as it did yesterday rather than dropping to zero; only days from here on are measured the new way.

## `+5 min` during a break adds five minutes

It replaced the remainder instead of adding to it. Four minutes into a ten-minute break, `+5` left you with five minutes rather than eleven — the button shortened the break it was asked to extend.

A grant now adds to whatever is left: six minutes remaining plus five is eleven. If the break is paused the five minutes are held with the rest and the break stays paused, because a grant is not a resume. At the break's own expiry screen nothing is left, so `+5` there means five minutes, as it always did.

This is the same rule the task editor already followed — time is added, never assigned.

## Everything else is unchanged

No new setting, no change to the checkpoint, and no change to what counts as work. The checkpoint still has no dismiss, no close, no timeout and no `Esc`. Switching a task still parks its block and resumes the remainder rather than re-granting the allocation. Block completion is still not task completion. Breaks still count as rest and never consume your daily capacity.

## Privacy

No account, no network calls, no telemetry. Everything is a local SQLite database under `~/Library/Application Support/xyz.gigiheristiawan.timebox/`. This release adds no entitlement and no new source of data.

## Upgrading

Your database is migrated automatically on first launch — a new table holding the work spans described above. It is additive: nothing existing is rewritten, and no day of recorded history is altered.

Migrations are forward-only and never removed, so going back to 0.3.1 still opens the same database: the new table is simply ignored, and the days it would have measured revert to the old whole-block attribution. Nothing is lost, and nothing needs doing by hand either way.

If you are coming from 0.2.0 or earlier, read the [0.3.0 notes](0.3.0.md) as well — in particular the one manual step there: every task added before 0.3.0 is stored as **Medium** priority regardless of what was picked, and can only be corrected with the editor.

## Install

Requires **macOS 13 or later**. Universal binary — Apple Silicon and Intel.

Open the DMG and drag TimeBox to Applications. The build is signed with a Developer ID certificate and notarized by Apple, so it opens without a Gatekeeper warning.

## Known limitations

- macOS only.
- **Sleep is not yet detected.** Closing the lid mid-block is still recorded as work, capped at the block's allocation. Quitting is handled; sleeping is not.
- Worked time before this release keeps its old per-block attribution: a block from an earlier version that crossed midnight still reports all of it on the day it started.
- A task's block duration can only be increased, never reduced. If you want a shorter block, remove the task and add it again.
- Idle is reported as one total. The causes behind it — paused, waiting at an unanswered checkpoint, no block at all — are recorded but not yet broken out in the UI.
- No task history browser; the Today summary covers the current day.
- No import, export, or sync — the database is local and yours to back up.
