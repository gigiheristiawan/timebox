TimeBox is a macOS menu bar utility for task rotation timeboxing:

> The timer controls **how long you work on a task**, not whether the task is completed.

0.2.0 adds the measure 0.1.0 was missing. The first release could tell you how long you *worked* — but the hours a day quietly loses, a morning that never starts, a block paused and forgotten, the app quit at 15:00, were invisible, and every summary flattered those days.

## Idle time, measured against a working window

Today now carries an **Idle in working hours** figure beside Worked and On break.

The name is the definition. Idle is *time inside your working window that no block covered* — not a claim about what you were doing. TimeBox does not observe you: no input monitoring, no screen-lock hook, no idle query to the system. Worked time is observed; idle is inferred from its absence, and only inside a span where you said you would be at the desk.

That asymmetry is deliberate at both edges of the window:

- Work recorded **outside** working hours still counts as work.
- Idle **outside** working hours is not counted at all — you never claimed to be there.
- A day with no blocks reports no idle. That is the holiday and the sick-day answer.

Set the window in **Settings → Working hours**: a start time, an end time, and which weekdays count. It is separate from daily capacity — 09:00–18:00 with 7h of capacity is a normal configuration. Capacity is how much of the day you intend to give; the window is when you are at the desk.

Under the hood idle is a set difference over intervals, not `window − worked − break`. The subtraction goes wrong the moment a block runs past your end time or a paused block spans a gap; the set difference does not.

## Quitting now parks the running block

**This reverses a 0.1.0 rule.** Previously `end_at` was absolute and the clock ran across a quit, so closing your laptop at 17:00 and reopening at 09:00 charged the intervening night to the task. Now the exit path parks the block, and the interval the app is closed is recorded as idle rather than work.

The anti-gaming rule is untouched: parking holds the **remainder** and never re-grants an allocation. Set a task down at 29:00 of a 30:00 block and you still resume with 1:00, whether you switched away or quit.

Consequently the 0.1.0 "are you sure you want to quit?" confirmation is gone. There is nothing left to warn about.

## Take a break on purpose

Breaks no longer have to come from a checkpoint. **Take a break** in the menu bar menu parks the work block and starts a break directly, and reads **End break** while one runs.

Without it, every rest taken between checkpoints was recorded as idle — a measure that punishes honesty. A deliberate break leaves the task at the queue head rather than rotating it to the tail, and unlike a switch it counts no interruption: that number measures churn between tasks, and stepping away for coffee is not churn.

## Fixes

- **`Cmd+Q` left the block running.** It reaches a different quit path than the popover's Quit item, and the park was hooked on the one it does not emit — so quitting from the menu parked correctly while `Cmd+Q` ran the clock across the quit. Both paths now park.
- **The menu bar's break item lied during a break.** It read *Take a break*, and clicking it did nothing. It now follows the state, and is disabled at a checkpoint.
- **Idle sat frozen on screen.** The figure was only repainted by the one-second ticker, which parks in exactly the states idle accrues in — paused, idle, waiting at a checkpoint. An open window showed a stale number until you acted. It now refreshes on window focus and every 10 seconds while the timer is stopped.

## Everything from 0.1.0 is unchanged

The checkpoint still has no dismiss, no close, no timeout and no `Esc`. Block completion is still not task completion. Breaks still carry no task and do not consume capacity. Nothing in Settings switches any of it off.

## Privacy

No account, no network calls, no telemetry. Everything is a local SQLite database under `~/Library/Application Support/xyz.gigiheristiawan.timebox/`. The idle feature adds no entitlement and no new source of data — it is arithmetic over blocks you already recorded.

## Upgrading

Your existing database migrates in place. The working window arrives with defaults — **09:00–18:00, Monday to Friday**. Check them in Settings before reading the Idle figure; a window you never set is not a window you agreed to.

Days recorded under 0.1.0 keep their numbers. Idle is computed from stored blocks, so earlier days report against the window you have now, not one you had then.

## Install

Requires **macOS 13 or later**. Universal binary — Apple Silicon and Intel.

Open the DMG and drag TimeBox to Applications. The build is signed with a Developer ID certificate and notarized by Apple, so it opens without a Gatekeeper warning.

## Known limitations

- macOS only.
- **Sleep is not yet detected.** Closing the lid mid-block is still recorded as work, capped at the block's allocation. Quitting is handled; sleeping is not.
- Idle is reported as one total. The causes behind it — paused, waiting at an unanswered checkpoint, no block at all — are recorded but not yet broken out in the UI.
- No task history browser; the Today summary covers the current day.
- No import, export, or sync — the database is local and yours to back up.
