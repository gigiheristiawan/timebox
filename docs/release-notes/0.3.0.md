TimeBox is a macOS menu bar utility for task rotation timeboxing:

> The timer controls **how long you work on a task**, not whether the task is completed.

0.3.0 makes the queue editable. A task you typed at 09:00 was, until now, fixed for the rest of the day: a title with a typo stayed wrong, a priority you picked was never stored at all, and a task that plainly needed another twenty minutes could only get them by waiting for its block to expire.

## Rename, re-prioritise, and grant more time

Hover a row in **Up next** — or the current task — and click `✎`. The row becomes an editor for its title and priority, with `+5m / +10m / +15m` beside them.

Time is **added, never assigned**. There is no field to type a new duration into, and that is deliberate: a settable allocation would let a running block be shortened into a checkpoint that arrives early and can then be dismissed, or a parked block cut below the remainder it was already promised. The only direction is up.

A grant lands in two places at once. It raises the task's allocation, so its *next* block is longer too, and it extends the block the task is holding right now — pushing a running countdown forward without giving back the time already burnt. Add 10 minutes with 4:00 left on the clock and you have 14:00, not a fresh 30.

**At a checkpoint the editor grants nothing.** `Extend` is how a checkpoint hands out time and it costs an explicit decision; if the editor could do it too, the checkpoint would have a side door. The whole product is that it does not.

Edits are a draft until you press Save, so Cancel genuinely cancels — including any time you added. A blank title is refused whole, taking the priority that rode with it, because an edit must not become the way to get a nameless task that adding one already refuses.

## Priority was never being saved

Every task you have ever added is stored as **Medium**, whatever you picked in the dropdown.

The add-task command compared the value the interface sends against the spelling the database uses, and the two never matched — so it fell back to Medium, silently, every time. Nothing surfaced the failure: the dropdown worked, the task appeared, and the dot beside it was Medium-coloured, which looked plausible.

That is fixed, and the priority you pick is now the priority that is stored.

**It does not repair existing tasks.** There is no record of what you originally chose, so nothing can be backfilled. Every task already in your database reads Medium and will keep reading Medium until you set it with the new editor. That is the one thing worth doing by hand after upgrading.

The marker itself is also easier to read: larger, shown in the menu bar popover as well as the main window — which showed no priority at all — and Low is now drawn as a hollow ring rather than a muted dot, so it is separable from Medium at a glance instead of by careful comparison of two similar colours.

## Drag-to-reorder now works

Dragging a row to reorder the queue did nothing, in either direction, for three unrelated reasons at once — the window's own drag handling was intercepting the gesture, the drag carried no payload for the browser engine to accept, and the reordering itself computed where to land the row *after* removing it, which made every downward drag put the row back exactly where it started.

All three are fixed. Rows move up and down, and the drop lands where you released it.

## Everything from earlier releases is unchanged

The checkpoint still has no dismiss, no close, no timeout and no `Esc`. Switching a task still parks its block and resumes the remainder rather than re-granting the allocation. Block completion is still not task completion. Idle is still inferred from the absence of work inside your working window, never observed. Nothing in Settings switches any of it off.

## Privacy

No account, no network calls, no telemetry. Everything is a local SQLite database under `~/Library/Application Support/xyz.gigiheristiawan.timebox/`. This release adds no entitlement and no new source of data.

## Upgrading

Your existing database opens unchanged — there is no migration in this release, and no day of recorded history is altered.

The one manual step is priority: see above. Nothing else needs attention.

## Install

Requires **macOS 13 or later**. Universal binary — Apple Silicon and Intel.

Open the DMG and drag TimeBox to Applications. The build is signed with a Developer ID certificate and notarized by Apple, so it opens without a Gatekeeper warning.

## Known limitations

- macOS only.
- **Sleep is not yet detected.** Closing the lid mid-block is still recorded as work, capped at the block's allocation. Quitting is handled; sleeping is not.
- A task's block duration can only be increased, never reduced. If you want a shorter block, remove the task and add it again.
- Idle is reported as one total. The causes behind it — paused, waiting at an unanswered checkpoint, no block at all — are recorded but not yet broken out in the UI.
- No task history browser; the Today summary covers the current day.
- No import, export, or sync — the database is local and yours to back up.
