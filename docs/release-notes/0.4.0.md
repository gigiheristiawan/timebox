TimeBox is a macOS menu bar utility for task rotation timeboxing:

> The timer controls **how long you work on a task**, not whether the task is completed.

0.4.0 is a feature release. The queue learns about work that comes back every day, a second timer can now watch how long you have been at the desk, and there is finally a way to look at a week rather than a day.

## Daily tasks

Standup, inbox, the exercise you keep not doing. Until now a recurring task had to be re-typed every morning, or ticked off once and never again — completing a task marks it `Done` and takes it out of the queue.

**Add task** and the task editor now carry a **Daily** checkbox. A daily task is never `Done` and never leaves the queue. Completing it means *done for today*: the row stays where you put it, dimmed and struck through, its action reading `✓ today`. Tomorrow it is simply outstanding again.

Done for today means **inert**, not merely deprioritised. Rotation steps over it and clicking it is refused, so the same task cannot be completed twice in one day and counted twice in Today. Completing a daily also discards any block it had parked, so tomorrow starts from a fresh allocation rather than yesterday's leftover twenty minutes.

There is **no reset at midnight** to miss. "Done today" is read from the completion stamp against local midnight each time the screen is drawn, so it is correct whether the app was quit for the night, asleep, or off for a week.

This is deliberately not a scheduler. Daily is the only recurrence: no weekly, no every-second-Tuesday, no due dates, and no catch-up for a day you missed. A daily missed yesterday is not owed today — it is outstanding, which it would have been anyway.

Both ways of granting time still work and now mean different things. `+5/+10/+15` in the editor raises the task's allocation **permanently** — a daily bumped to 45m starts at 45m every day. `Extend` at a checkpoint raises **today's** block only, and that block is discarded with the day.

Turning the Daily checkbox back off on a task already ticked today clears the tick, so it is cleanly outstanding rather than sitting in neither column.

## Pomodoro mode

The task timer answers *how long do I stay on this task*. It has nothing to say about *how long have I been sitting here*. A task given 90 minutes runs 90 minutes and the app never interrupts.

Pomodoro mode is a **second clock beside the first**, not a change to the first. Your allocations are untouched: a 45-minute task still gets 45 minutes, its checkpoint still asks the same question. The Pomodoro clock only ever asks one thing — *break, or keep going?*

It counts **only running work time**. Twenty-five minutes of actual work, however long that takes on the wall clock: it parks while you are paused, at a checkpoint, and during a break. Wall-clock counting would greet you back from an hour's meeting with "time for a break", which is the opposite of useful.

At twenty-five minutes the task block is parked with its remaining time held, and a checkpoint opens with two doors: **Take a break** and **Skip & continue**. It has no dismiss, no close, no timeout and no `Esc`, like every other checkpoint. What is forced is the decision, not the break — a task two minutes from done should not have to be abandoned to a five-minute break. The prompt decides the break and nothing else: your task is neither completed nor rotated, and it is still current when you resume.

Any break resets the clock, whichever door you came through — the Pomodoro prompt, a task checkpoint's break option, or the tray. *Skip & continue* resets it too, so skipping buys another full twenty-five rather than another prompt in a minute's time.

**When both clocks are due at once, the task checkpoint wins** and the Pomodoro prompt is dropped rather than queued — two blocking windows for one moment is the interruption you were trying to bound. The task checkpoint can do everything the Pomodoro prompt can, and its break option arrives pre-checked when a Pomodoro was due.

The toggle is in **Settings**, the **tray menu** and the **popover**, because the mode is meant to be flipped mid-day. Switching it on starts a fresh twenty-five from that instant; switching it off discards the clock. It is refused while a checkpoint is open, which is not an exit from one.

The work interval is fixed at 25 minutes. The break is whatever your existing default break length is — a Pomodoro break is a break, and a second break-length setting would be two answers to one question.

## Weekly report

A **Report** tab beside **Focus** at the top of the main window.

Seven day rows for one week, Monday to Sunday: weekday, date, worked time, a bar against that day's target, and the day's breaks, idle and out-of-hours time. The week's total worked reads against `your daily capacity × your working weekdays` — `12h 20m of 20h · 62%` — with tasks completed, blocks completed, and how often you switched away early. Up to three top tasks with their share of the week, and the idle breakdown in the same words the Today strip uses.

`‹` and `›` — or `←` and `→` while the tab is open — move a week at a time. Back is unbounded; forward stops at this week.

**All seven days are always shown**, including the ones with nothing on them, and including the rest of the current week. A blank Thursday is information. The current week is measured against the **whole** week's target rather than the days elapsed, so Tuesday reading 40% is the truth about the week rather than a flattering fraction of it.

A day with no target that has work on it — a Saturday, if Saturday is not a working day — reads as over target rather than exempt from one.

The report **describes; it never changes anything**. It is read-only, it adds no new record of its own, and every figure in it comes from the same definition of a day the Today strip already uses — the two cannot drift apart. The Report tab is a view, not a mode: the timer keeps running behind it and a checkpoint still takes the window when it opens.

## Three things the report cannot recover

These are limits of what earlier versions recorded, not of the report:

- **A daily ticked off several days running counts once.** A task stores its *last* completion, not a log of them, so a standup done Monday, Tuesday and Wednesday reports one completion for the week — on Wednesday. All three of its blocks and all of its time are reported correctly; it is the tick that is not repeatable.
- **Switched-early is counted over blocks that *ended* in the week**, since the counter carries no timestamp of its own.
- **Idle while waiting at a checkpoint** is reported from the recorded idle spans rather than the older lifetime away counter, which measures the same thing less well.

## Your settings are applied to the past as they are now

A past week's target, working window, idle and out-of-hours figures are all computed from your **current** settings. There is no record of what they were at the time. So raising your capacity from 4h to 6h lowers last month's attainment, and turning Saturday on gives every past Saturday a target.

This is accepted rather than fixed: the report is a view of today's expectations applied to the record, and reads correctly under that description.

## Everything else is unchanged

No change to the checkpoint — still no dismiss, no close, no timeout, no `Esc`. Switching a task still parks its block and resumes the remainder rather than re-granting the allocation. Block completion is still not task completion. Breaks still count as rest and never consume your daily capacity.

## Privacy

No account, no network calls, no telemetry. Everything is a local SQLite database under `~/Library/Application Support/xyz.gigiheristiawan.timebox/`. This release adds no entitlement and no new source of data.

## Upgrading

Your database is migrated automatically on first launch: one column marking a task daily, and one recording where the current Pomodoro is counting from. Both are additive — no existing row is rewritten and no day of recorded history is altered. Every task you already have is an ordinary one, and Pomodoro mode starts off.

Migrations are forward-only, so going back to 0.3.2 opens the same database and ignores both. The weekly report needs no migration at all — it is computed from records you already have, so **the week you are in now is already in it** the moment you install.

If you are coming from 0.2.0 or earlier, read the [0.3.0 notes](0.3.0.md) as well — in particular the one manual step there: every task added before 0.3.0 is stored as **Medium** priority regardless of what was picked, and can only be corrected with the editor.

## Install

Requires **macOS 13 or later**. Universal binary — Apple Silicon and Intel.

Open the DMG and drag TimeBox to Applications. The build is signed with a Developer ID certificate and notarized by Apple, so it opens without a Gatekeeper warning.

## Known limitations

- macOS only.
- **Sleep is not yet detected.** Closing the lid mid-block is still recorded as work, capped at the block's allocation — and now counts toward the Pomodoro clock as well. Quitting is handled; sleeping is not. A crash, unlike a clean quit, can therefore make the Pomodoro prompt fire immediately on relaunch.
- Pomodoro's twenty-five minutes is not configurable, the break offered is one length, and *Skip & continue* means the break is never truly forced.
- Daily is the only recurrence, and there are no streaks — the report counts a daily's completion once per week, as above.
- The report has no export, no charts, and no range other than a week.
- Worked time recorded before 0.3.2 keeps its old per-block attribution: a block from an earlier version that crossed midnight still reports all of it on the day it started.
- A task's block duration can only be increased, never reduced. If you want a shorter block, remove the task and add it again.
- No import, export, or sync — the database is local and yours to back up.
