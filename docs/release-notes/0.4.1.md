TimeBox is a macOS menu bar utility for task rotation timeboxing:

> The timer controls **how long you work on a task**, not whether the task is completed.

0.4.1 is a fix release. On a Mac that has been connected to an external monitor, the checkpoint window could open at the wrong size and in the wrong place — half off the screen, with its buttons past the edge.

## The checkpoint opens on your main display, correctly sized

Two things were wrong, and on a two-monitor desk they compounded.

**It opened on the wrong screen.** The checkpoint was placed on whichever display the mouse pointer was on — which is precisely where you are *not*: the pointer is wherever it was abandoned when you stopped using the mouse. It now opens on the display macOS calls the **Main display** (System Settings → Displays), the same chosen screen every time. The pointer's screen is kept only as a fallback if that cannot be resolved.

**It kept the size of a monitor that was no longer there.** The window is built once and reused, and its geometry was only ever set at that first build. A checkpoint first shown on a large external monitor kept that frame after the monitor was unplugged, so it came back sized for a screen the Mac no longer had — landing partly off the built-in display. It is now re-fitted to the main display **every time it is shown**, so unplugging a monitor, plugging one in, or changing which display is the main one all take effect at the next checkpoint with nothing to restart.

The mismatch of pixel densities in a Retina-plus-1× pair made the same bug worse rather than milder: the window could open at roughly twice the screen, with its content centred somewhere past the bottom-right corner.

Nothing about the checkpoint itself changed. It still has no dismiss, no close, no timeout and no `Esc`, and it still takes the whole screen it opens on.

## Everything else is unchanged

No migration, no schema change, no new setting, and no change to how time is recorded. Everything in 0.4.0 — daily tasks, Pomodoro mode, the weekly Report tab — is as it was.

Switching a task still parks its block and resumes the remainder rather than re-granting the allocation. Block completion is still not task completion. Idle is still inferred from the absence of work inside your working window, never observed.

## Privacy

No account, no network calls, no telemetry. Everything is a local SQLite database under `~/Library/Application Support/xyz.gigiheristiawan.timebox/`. This release adds no entitlement and no new source of data.

## Upgrading

Your existing database opens unchanged. There is no migration in this release and nothing to do by hand.

If you are coming from 0.3.2 or earlier, read the [0.4.0 notes](0.4.0.md) as well — it carries two migrations, and it is where daily tasks, Pomodoro mode and the report arrived.

If you are coming from 0.2.0 or earlier, read the [0.3.0 notes](0.3.0.md) too — in particular the one manual step there: every task added before 0.3.0 is stored as **Medium** priority regardless of what was picked, and can only be corrected with the editor.

## Install

Requires **macOS 13 or later**. Universal binary — Apple Silicon and Intel.

Open the DMG and drag TimeBox to Applications. The build is signed with a Developer ID certificate and notarized by Apple, so it opens without a Gatekeeper warning.

## Known limitations

- macOS only.
- **The checkpoint always opens on the main display**, which is not configurable. If you want it on the other screen, change which display is the main one in System Settings → Displays.
- **Sleep is not yet detected.** Closing the lid mid-block is still recorded as work, capped at the block's allocation — and counts toward the Pomodoro clock as well. Quitting is handled; sleeping is not.
- Pomodoro's twenty-five minutes is not configurable, the break offered is one length, and *Skip & continue* means the break is never truly forced.
- Daily is the only recurrence, and there are no streaks.
- The report has no export, no charts, and no range other than a week.
- Worked time recorded before 0.3.2 keeps its old per-block attribution: a block from an earlier version that crossed midnight still reports all of it on the day it started.
- A task's block duration can only be increased, never reduced. If you want a shorter block, remove the task and add it again.
- No import, export, or sync — the database is local and yours to back up.
